## 1. 整体方案

该仓库采用「统一网络层 + 集中式错误回调 + 分级日志」的错误处理架构，覆盖 Mock 服务端、@jl/framework 组件库以及 demo 应用三层。

- **Mock 服务**（`packages/mock`）：基于 Express，通过 `utils/dataUtils.ts` 的 `repData(data, code=200, msg='')` 统一包装响应体 `{code, message, data}`，所有路由均返回此结构；未显式设置错误码时默认 200。
- **网络层**（`packages/framework/src/utils/netUtils/index.ts`）：封装 axios，在请求/响应拦截器中集中处理鉴权失败（401）、网络异常等，并通过注入的 `ErrorHandler(code, msg, 'request'|'response')` 回调交由上层决定 UI 表现。
- **数据请求层**（`packages/framework/src/stores/store/utils/storeReq.ts`）：实现请求去重、竞态取消（AbortController）、失败重试（线性递增延迟，基础 300ms × attempt），并在取消/失败时通过 `logger` 输出 debug/warn/error。
- **日志系统**（`packages/framework/src/utils/sysUtils/logger.ts`）：自研轻量 logger，支持 `debug/info/warn/error/silent` 五级，级别由构建期环境变量 `VITE_LOG_LEVEL` 控制，运行时可通过 `setLogLevel` 调整。

## 3. 架构与约定

### 3.1 网络错误传播路径

1. 业务代码通过 `HandlerBase.get/post` → `NetUtils.get/post` → axios 发起请求。
2. **请求拦截器**：若无 token，调用 `errorHandler(401, '未找到授权Token', 'request')` 并 reject。
3. **响应拦截器**：非 cancel 错误提取 `status` 和 `message`，调用 `errorHandler(code, message, 'response')` 后 reject。
4. **storeReq.attemptSend**：捕获异常，若 `NetUtils.isCancel(error)` 则静默退出（竞态取消）；否则记录 warn 并按 `req.retry` 配置重试，超过次数后重新抛出错误。
5. **调用方**：`fetchData` / `send` 最终将 Promise 暴露给 handler/view，由业务层 catch 或交给 React 边界处理。

### 3.2 请求级错误策略

- **去重**：相同 `req.id` + 序列化后的 params 复用同一 Promise（`inflight Map`）。
- **竞态取消**：新请求 abort 旧请求的 AbortController，被取消的请求在 `attemptSend` 中通过 `NetUtils.isCancel` 识别并静默退出，不写数据、不触发子请求。
- **重试**：`RETRY_BASE_DELAY = 300`，第 n 次重试等待 `300 * (attempt+1)` ms；`req.retry` 可配置最大重试次数。
- **依赖检查**：父请求未完成时先递归 `fetchData(parentIds)`，失败则 warn 并中止。

### 3.3 结构化错误类型

- 客户端统一使用 `Result<T>` 接口 `{code: number; message: string; data?: T}` 描述 API 响应。
- Mock 服务通过 `repData` 生成该结构，业务侧据此判断成功/失败。
- 框架内部异常（如未注册 viewId、handler 缺失）直接使用原生 `Error` 抛出，而非自定义错误类。

### 3.4 日志规范

- 禁止直接 `console.log`，统一通过 `logger.debug/info/warn/error`。
- 开发环境默认 `debug`，生产默认 `warn`，可通过 `import.meta.env.VITE_LOG_LEVEL` 或 `setLogLevel` 调整。
- storeReq 中：取消→debug，重试→warn，最终失败→error。

## 4. 约束与约定

- **Mock 端**：所有路由必须通过 `repData` 返回 `{code, message, data}` 结构；未显式传参时默认 `code=200`。Express 入口未注册全局错误中间件，路由内需自行处理异常。
- **网络层**：所有 HTTP 异常必须经 `NetUtils` 发起；401 一律走 `handleUnauthorized` 跳转登录。
- **storeReq**：`req.retry` 为可选配置，默认 0 次重试；`signal` 用于竞态取消，不可忽略。
- **视图/Handler 初始化**：非法 viewId 会直接抛错（`storeView.getView`、`handlerBase.getHandler`），调用方应确保 viewId 有效后再访问。
- **日志**：仓库约定不引入第三方日志框架，所有调试输出收敛到 `logger`，级别受 `VITE_LOG_LEVEL` 控制。

## 5. 适用性说明

本仓库存在完整的错误处理链路（Mock 响应包装 → axios 拦截器 → storeReq 重试/取消 → 分级日志），因此该类别适用，置信度为 high。
