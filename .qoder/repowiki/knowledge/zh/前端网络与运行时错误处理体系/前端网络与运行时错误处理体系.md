## 1. 整体方案

该仓库采用「框架层统一封装 + 应用层注入回调」的前端错误处理模式：
- 网络请求通过 `packages/framework/src/utils/netUtils` 基于 axios 封装，集中处理鉴权、超时、取消等异常；
- 全局错误以「code + message」的 `Result<T>` 结构返回，由调用方（Handler/Data）自行判断业务码；
- 非网络类运行时异常在框架内部直接 `throw new Error(...)`，由上层调用处捕获；
- 日志通过 `@utils/sysUtils/logger` 统一输出，支持按环境变量/运行时调整级别。

## 2. 关键文件与职责

| 文件 | 职责 |
|---|---|
| `packages/framework/src/utils/netUtils/index.ts` | 创建 axios 实例、注册请求/响应拦截器、统一透传错误到 `ErrorHandler` |
| `packages/framework/src/utils/netUtils/interface.ts` | 定义 `Result<T>` 统一返回结构、`ErrorHandler` 类型、token key |
| `packages/framework/src/utils/netUtils/tokenUtils.ts` | token 存取与过期检查 |
| `packages/framework/src/handler/handlerBase.ts` | 暴露 `get/post` 方法，透传 NetUtils 的错误；对 handler 查找失败抛 `Error` |
| `packages/framework/src/utils/sysUtils/logger.ts` | 统一日志工具，级别受 `VITE_LOG_LEVEL` 控制 |
| `apps/demo/src/init/net.ts` | 应用侧初始化 NetUtils，注入全局错误回调（401 跳转登录 + antd message 提示） |

## 3. 架构与约定

### 3.1 网络错误处理链路
1. 应用启动时调用 `NetUtils.init(baseURL, loginUrl, loginAPI, errorHandler, tokenExpireTime)`，将全局错误回调注入框架。
2. **请求拦截器**：无 token 时调用 `errorHandler(401, '未找到授权Token', 'request')` 并 `Promise.reject(new Error('未找到授权Token'))`；拦截器自身异常调用 `errorHandler(500, ...)`。
3. **响应拦截器**：忽略 axios cancel 错误（竞态取消场景），其余错误提取 `status` 与 `data.message` 后调用 `errorHandler(code, message, 'response')`，再 `Promise.reject(error)`。
4. Handler 的 `get/post` 直接返回 `NetUtils.get/post` 的 `Result<T>`，业务层根据 `result.code` 判断成功与否。

### 3.2 业务返回结构
所有接口统一返回 `Result<T>`：
```ts
interface Result<T> {
  code: number;
  message: string;
  data?: T;
}
```
登录失败、头缺失、token 缺失等非网络异常也返回 `{ code: 400/状态码, message }`，而非抛出异常。

### 3.3 运行时异常
框架内部遇到不可恢复状态时使用原生 `throw new Error(...)`，例如 `handlerBase.ts` 中找不到对应 viewId 的 handler 时抛出 `Error(`${viewId}对应的handler不存在`)`。这类异常不属于网络错误，应由调用方 try/catch 或 React error boundary 处理。

### 3.4 日志与可观测性
`logger` 提供 `debug/info/warn/error` 四个级别，默认级别由 `import.meta.env.VITE_LOG_LEVEL` 决定（开发环境 debug，生产 warn），可通过 `setLogLevel()` 运行时调整。仓库约定不引入第三方日志框架，所有调试输出收敛于此。

## 4. 约定与约束

- **禁止直接使用 axios**：所有 HTTP 请求必须通过 `HandlerBase.get/post` 或 `NetUtils.get/post`，确保拦截器与全局错误回调生效。
- **错误回调契约**：`ErrorHandler` 签名固定为 `(code: number, msg: string, type: 'request' | 'response') => void`，应用必须实现 401 分支以触发 `NetUtils.handleUnauthorized()` 跳转登录。
- **统一返回码**：业务层不应依赖 Promise reject 来判断业务失败，应读取 `Result.code`；仅网络层异常会走 reject。
- **取消请求不触发全局错误**：axios cancel 错误被显式跳过全局 `errorHandler`，避免误报。
- **日志级别不可绕过**：所有日志输出需经 `logger`，且级别过滤在服务端构建期/运行期生效，禁止直接 `console.*` 输出调试信息。
- **handler 查找失败即抛错**：`HandlerBase.getHandler` 在未找到 view 或 handlerClass 时直接 `throw new Error(...)`，属于编程错误，不应被当作业务错误处理。
