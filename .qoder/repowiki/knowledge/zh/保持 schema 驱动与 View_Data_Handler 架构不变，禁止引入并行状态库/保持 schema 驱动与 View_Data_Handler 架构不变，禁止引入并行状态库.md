# 保持 schema 驱动与 View/Data/Handler 架构不变，禁止引入并行状态库

_来源：7c359f6 → 2bdcd49 提交周期内记录的编码计划——内容为规划时意图，实现可能滞后或有出入。_

**状态：** accepted

## 背景
本次优化涉及 Context 分发 store + zustand 路径级订阅模式，但前期分析确认该模式本身健康，只需修复正确性、补工具链与性能债。

## 决策驱动
- 保护现有核心资产（schema 驱动、compFactory）
- 避免重构破坏面
- 维持单一状态方案

## 备选方案
- **重构为类式三段 → hooks** _（已否决）_ — 优点：理论上更现代；缺点：收益低、破坏面大
- **替换 schema 驱动与 compFactory** _（已否决）_ — 优点：无；缺点：框架核心资产被替换
- **引入 Redux/jotai 等并行状态库** _（已否决）_ — 优点：无；缺点：两套状态并存增加心智负担
- **保持现状并渐进优化** — 优点：零架构风险、可分阶段交付；缺点：遗留问题逐步消化

## 决策
明确不做类式三段→hooks 重构、不替换 schema 驱动与 compFactory、不引入 Redux/jotai 等并行状态库；所有变更围绕现有架构做正确性修复、工具链补齐与性能加固。

## 影响
框架演进以增量方式推进，每阶段独立可回归；长期需在类型安全收口与请求层演进上持续投入。
