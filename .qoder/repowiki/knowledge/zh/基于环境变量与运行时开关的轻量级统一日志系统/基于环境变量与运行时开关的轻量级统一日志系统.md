## 1. 系统/方案概述

仓库未引入任何第三方日志框架（如 winston、pino、bunyan），而是在 `packages/framework/src/utils/sysUtils/logger.ts` 中实现了一个极简的统一日志工具，所有调试输出收敛到该模块，通过浏览器原生 `console.*` 输出。

日志级别由构建期注入的环境变量 `VITE_LOG_LEVEL` 控制，并支持运行时通过 `setLogLevel()` 动态调整。默认策略：开发环境为 `debug`，生产环境为 `warn`。

## 2. 关键文件

- `packages/framework/src/utils/sysUtils/logger.ts` — 日志核心实现，定义 `LogLevel` 类型、级别权重表、环境变量读取、运行时级别切换以及 `logger.debug/info/warn/error` 四个方法。
- `packages/framework/src/index.ts` — 将 `logger`、`getLogLevel`、`setLogLevel`、`LogLevel` 类型作为框架公共 API 重新导出，供应用及子模块消费。
- `packages/framework/src/stores/store/utils/pageRuntime.ts` — 框架 store 层大量使用 `logger.warn/error/debug` 记录请求失败、循环依赖、重试等运行时异常。
- `packages/framework/src/stores/store/utils/storeData.ts` — 数据节点依赖校验时通过 `logger.error/warn` 输出。
- `packages/framework/src/comp/view/table/utils/useRowIdentityList.ts` — 表格渲染降级场景下通过 `logger.warn` 提示回退行为。

## 3. 架构与约定

- **集中式单例**：`logger.ts` 以模块单例形式维护当前 `currentLevel`，所有调用方直接 `import logger from '@utils/sysUtils/logger'`，无实例化开销。
- **级别权重过滤**：内部用 `LEVEL_WEIGHT: Record<LogLevel, number>` 把 `debug(0) < info(1) < warn(2) < error(3) < silent(4)` 排序，`enabled(level)` 判断是否输出，避免在低级别下执行昂贵参数计算。
- **环境变量驱动**：通过 `import.meta.env.VITE_LOG_LEVEL` 读取构建期注入的值；若值非法则回退到 `DEV ? 'debug' : 'warn'`。
- **运行时覆盖**：`setLogLevel()` 可覆盖环境变量设置，优先级更高，便于调试时临时提升级别。
- **输出格式**：`debug` 前缀 `[debug]`，`info` 前缀 `[info]`，`warn`/`error` 直接使用 `console.warn`/`console.error`，不附加额外字段——属于非结构化、面向人类阅读的 console 风格。
- **框架对外暴露**：`src/index.ts` 显式 `export { default as logger, getLogLevel, setLogLevel }` 并导出 `LogLevel` 类型，使框架使用者可通过统一入口接入日志能力。

## 4. 约定与约束

- **禁止引入第三方日志库**：`logger.ts` 顶部注释明确“仓库约定不引入第三方日志框架,所有调试输出统一收敛到此处”，这是本仓库对 logging_system 的核心约束。
- **日志级别来源单一**：仅通过 `VITE_LOG_LEVEL` 环境变量配置，不支持配置文件或运行时 API 以外的方式。
- **silent 级别存在但未被调用**：`LogLevel` 包含 `silent`，且 `enabled('silent')` 恒为 false（权重最高），可用于完全关闭日志，但代码中未见实际使用场景。
- **错误语义区分**：业务异常（如请求失败）使用 `logger.error`，状态性告警（如依赖缺失、降级回退）使用 `logger.warn`，调试信息使用 `logger.debug`，形成一致的语义约定。
- **ESLint 配合**：根目录 `eslint.config.js` 启用 `no-debugger` 规则（warn），间接鼓励使用 `logger.debug` 而非 `debugger` 断点。
- **未实现的功能**：无结构化字段（如 timestamp、traceId、module）、无多 sink（文件/远程上报）、无异步日志队列、无性能采样集成（性能统计走独立的 `perfTrackerUtils`）。
