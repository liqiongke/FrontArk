## 架构总览
数据同步的关键流程：
- 视图通过 useReq 获取当前视图的请求参数并触发刷新
- storeBase 将 refreshByViewId 委托给 PageRuntime.refreshByViewId
- PageRuntime 根据 viewId 解析请求节点，构建参数，检查依赖，调用 NetUtils.get
- NetUtils 在请求前注入 Token，并在响应拦截器中统一错误处理
- 返回数据经 NetDataUtils 提取核心数据与视图参数，并初始化 key
- 数据写入 store.data，同时记录请求元信息到 reqMeta，随后触发子节点请求

## 性能考虑
- **请求去重与竞态取消**
  - inflight Map 登记进行中请求，相同参数的并发请求复用同一个 Promise
  - 新请求取代旧请求时通过 AbortController 取消，避免资源浪费
- **依赖顺序与并行度**
  - checkDependencies 串行等待父级数据就绪；子节点请求通过 Promise.all 并行执行
- **数据去重与键值**
  - NetDataUtils.initData 为对象/数组分配稳定 key，有助于列表渲染与 diff 优化
- **大列表优化**
  - 服务端分页：通过 @pagination 字段配合后端分页接口
  - 前端虚拟滚动：结合 key 稳定的数据结构，减少重渲染开销
  - 增量更新：仅更新变更项，避免整表替换
- **防抖与节流**
  - setDataDebounce 提供300ms默认延迟，同一路径的连续写入合并为最后一次
  - dispose 时立即提交未落盘的防抖输入，避免数据丢失
- **重试机制**
  - 线性递增重试间隔：300ms、600ms、900ms...
  - 可配置的 retry 次数，401/403 不重试

## 故障排查指南
- **常见错误来源**
  - 网络层：无 Token、超时、服务端错误码；由 NetUtils 拦截器统一回调 errorHandler
  - 业务层：请求不存在、依赖未就绪；PageRuntime 会输出警告日志
  - 循环依赖：checkDependencies 检测到循环依赖时会报错并终止请求
- **用户反馈**
  - 应用层在 net.ts 中通过 message.error 展示错误信息；401 时调用 handleUnauthorized 跳转登录
- **调试建议**
  - 查看 store.data 与 store.reqMeta 中的请求状态与结果
  - 检查 DataProps 的 url、params、path 映射是否正确
  - 确认 parentIds/childIds 依赖链是否符合预期
  - 使用浏览器开发者工具监控 inflight 请求和 debounce 任务

## 结论
该数据同步方案通过 PageRuntime 统一管理请求生命周期，实现了请求去重、竞态取消、重试机制和防抖写入等高级特性。结合 NetUtils 的拦截器与 NetDataUtils 的数据标准化，实现了从参数构建、依赖检查、网络请求到本地存储的完整闭环。通过 getReqParams 与 refreshByViewId，视图可灵活读取与刷新数据；借助 key 稳定化与分页/增量策略，可支撑大规模列表场景。错误处理与未授权流程清晰，便于统一用户体验。

**更新** 新的 PageRuntime 实现相比旧的 StoreReq 提供了更强大的功能：请求去重避免重复请求、竞态取消防止资源浪费、重试机制提高容错性、防抖写入优化用户体验。

  - ReqStatus：'idle' | 'pending' | 'success' | 'error' 请求状态
- **数据流要点**
  - 请求参数：criteria + params 映射
  - 数据存储：store.data[id] = 标准化后的数据
  - 请求元信息：reqMeta[id].status = 请求状态，responseParams = 响应参数
  - 请求去重：inflight Map 登记进行中请求，相同参数复用 Promise
  - 竞态取消：AbortController 取消旧请求，新请求取代旧请求
