## 简介
本模块基于 Zustand 构建，提供统一的 StoreBase 基类能力，封装了"数据、视图、处理器、请求参数"等状态的管理，并通过 React Context 注入到组件树中。同时提供用户级 store 的通用模板，便于在业务中快速创建全局状态。**最新更新**：Store层性能优化，包括路径解析缓存机制、数组索引优化和并发请求处理增强，显著提升了大数据量场景下的性能和响应速度。

### 数据绑定与响应式更新
- 读取：useData/useDataById 通过 Zustand selector 精确订阅 path 对应的值，避免无关重渲染。
- 立即更新：useDataStoreState 直接调用 setData，触发最小化更新。
- 本地缓存+防抖：useDataState 在组件内缓存值，并通过 setDataDebounce 延迟提交到 store，减少频繁更新带来的开销。
- 防抖实现：基于 Map 记录每个 path 的定时器，重复设置会取消旧定时器，最终合并为一次更新。

## 性能优化详解

### 路径解析缓存机制
**新增功能**：在 `storeDataPath.ts` 中实现了智能的路径解析缓存系统，显著提升高频数据访问性能。

- **字面量路径缓存**：使用 `literalPathCache` Map 存储已解析的路径结果，避免重复计算
- **缓存策略**：最大缓存 2000 条记录，超过限制时自动清理
- **缓存键生成**：针对不同路径类型采用不同的序列化策略
  - 数字路径：`n:${path}`
  - 数组路径：`a:${JSON.stringify(path)}`  
  - 字符串路径：`s:${path}`
- **引用稳定性**：缓存返回的是同一数组引用，确保 Zustand selector 的有效性

### 数组索引优化
**新增功能**：使用 WeakMap 实现引用级别的数组索引缓存，避免重复的 findIndex 操作。

- **WeakMap 缓存**：`activeIndexCache` 以数组引用为键，存储 KeyAttr 到下标的映射
- **自动失效**：当数组被修改（immer 生成新引用）时，WeakMap 自动清理旧索引
- **智能重建**：首次查询失败时回退到 findIndex，成功后重建索引以提高后续性能
- **O(1) 查找**：缓存命中时提供常数时间的索引查找，替代 O(n) 的线性搜索

### 并发请求处理增强
**增强功能**：在 `storeReq.ts` 中实现了完整的并发请求管理机制，支持请求去重和竞态取消。

- **请求去重**：相同参数的并发请求共享同一个 Promise，避免重复网络请求
- **竞态取消**：新请求自动取消未完成的旧请求，防止数据竞争
- **重试机制**：支持可配置的请求重试，按指数退避策略增加延迟

## 故障排查指南
- 未确认的 viewId：当 getView 传入空或不存在的 viewId 时会抛出错误，需检查视图初始化是否正确。
- 数据请求节点不存在：初始化阶段若父节点不存在会发出警告并跳过，需检查 DataProps 中的 path/id 配置。
- 重复的数据请求 id：初始化时若检测到重复 id 会跳过并警告，需确保 id 唯一。
- 防抖未生效：检查 setDataDebounce 的 path 是否一致，Map 中 key 由路径字符串生成，不一致会导致多个定时器并存。
- **路径缓存问题**：如果路径解析结果不符合预期，检查路径是否包含动态引用（如 @Active），这类路径不会被缓存。
- **并发请求冲突**：如果出现请求被意外取消的情况，检查是否存在频繁的重复请求，考虑增加请求去重逻辑。
