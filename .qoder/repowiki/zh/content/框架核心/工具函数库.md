## 简介
本工具函数库为前端应用提供网络请求、路径处理、性能监控、统一日志管理和渲染诊断等通用能力，并通过统一的导出入口对外暴露。其设计目标是：
- 统一网络层封装与错误处理，简化业务调用
- 提供稳定可靠的路径计算与视图路径工具
- 以无侵入方式对关键函数进行性能埋点与统计
- 通过 Store 数据/请求工具将网络结果与状态管理打通
- 提供集中式日志管理功能，支持可配置的日志级别和运行时调整
- **新增** 提供完整的渲染诊断工具链，帮助定位组件渲染问题、追踪数据变更来源和分析提交性能

## 项目结构
- 应用初始化入口位于 apps/demo/src/init，负责启动时配置网络模块
- 框架核心工具集中在 packages/framework/src/utils，包含 netUtils、pathUtils、viewPathUtils、sysUtils 等
- sysUtils 目录包含统一日志系统和性能监控工具
- utils 目录下新增 renderProbe.ts 和 renderProbeCommit.tsx，提供完整的渲染诊断能力
- 数据与请求工具位于 stores/store/utils，用于在 Store 中读写数据并触发请求
- 统一导出由 packages/framework/src/index.ts 完成，便于外部按需引入

## 核心组件
- 网络请求工具 NetUtils：基于 Axios，提供初始化、登录、鉴权、GET/POST 等方法，内置请求/响应拦截器与统一错误回调

- 性能监控 PerfTrackUtils：对任意函数进行包装，统计调用次数、耗时、异常等指标，并提供打印与清零能力
- 统一日志工具 logger：提供集中式日志管理功能，支持可配置的日志级别和运行时调整
- **渲染探针系统**：提供完整的组件渲染诊断能力，包括组件执行计数、props变化追踪、memo边界检测和提交性能分析
- Store 数据/请求工具：在 Store 上下文中读取/设置数据，并根据视图配置发起网络请求，自动处理子节点级联请求

## 详细组件分析

### 网络请求工具 NetUtils
- 职责
  - 初始化基础 URL、登录页地址、登录接口、Token 过期时间
  - 创建 Axios 实例并注入请求/响应拦截器
  - 统一错误处理回调，支持 401 未授权跳转
  - 提供登录、令牌检查、GET/POST 便捷方法
- API 概览
  - init(baseURL, loginUrl, loginAPI, errorHandler, tokenExpireTime?)
    - 参数
      - baseURL: string
      - loginUrl: string
      - loginAPI: string
      - errorHandler(code, message, type): void
      - tokenExpireTime?: number（默认 7200000）
    - 返回: void
  - login(data): Promise<Result<T>>
  - checkToken(): void
  - handleUnauthorized(): void
  - get(url, params?): Promise<Result<any>>
  - post(url, data?): Promise<Result<any>>
- 使用示例（概念性）
  - 应用启动时调用 init，传入环境变量中的基础地址、登录页与登录接口，并实现错误提示逻辑
  - 业务页面调用 get/post 获取数据，或调用 login 完成登录后刷新 Token
- 注意事项
  - 请求头需携带 Authorization；若缺失会触发 401 错误回调
  - 跨域需服务端暴露必要的响应头以便读取 Token

### 渲染探针系统
- 职责
  - 提供完整的组件渲染诊断能力，帮助定位渲染性能问题和数据变更来源
  - 支持组件函数执行计数和 props 变化追踪
  - 提供 React.memo 边界检测，识别哪些 props 导致 memo 失效
  - 追踪 Store 写入操作，定位数据变更的调用栈
  - 分析 React 提交阶段的性能表现
- API 概览
  - useRenderProbe(label: string, props?: object): void
    - 在组件函数体首行调用，记录组件执行次数和 props 变化
  - createMemoProbe<P extends object>(name: string): (prev: P, next: P) => boolean
    - 包装 React.memo 的比较函数，记录 memo 边界被打破的原因
  - traceStoreWrites<T>(useStore: StoreApi<T>, label?: string): () => void
    - 临时包装 zustand store 的 setState，记录每次写入的调用栈
  - traceStoreNotify<T>(useStore: StoreApi<T>, label?: string): () => void
    - 通过 subscribe 观察 store 通知，记录变化切片
  - setProbeEnabled(value: boolean): void
    - 运行时开启/关闭探针功能
  - probeEnabled(): boolean
    - 查询探针是否启用
- 使用示例（概念性）
  - 在组件中使用：`useRenderProbe('MyComponent', props)`
  - 包装 memo：`React.memo(Component, createMemoProbe('MyComponent'))`
  - 追踪 store 写入：`const cleanup = traceStoreWrites(useStore, 'userStore')`
  - 分析提交性能：`<CommitProbe id="table1"><Table /></CommitProbe>`
- 设计要点
  - 通过 localStorage 控制开关，默认关闭避免影响生产性能
  - 使用 console.debug 输出，配合日志级别控制
  - 浅比较 props，与 React.memo 默认比较语义一致
  - 捕获调用栈信息，帮助定位数据来源

### CommitProbe 组件
- 职责
  - 基于 React.Profiler 的提交性能分析组件
  - 统计组件提交的批次、阶段（mount/update）和实际耗时
  - 仅在探针开启时输出调试信息，不影响生产环境性能
- API 概览
  - CommitProbe({ id: string, children?: ReactNode }): ReactNode
    - 参数
      - id: string（组件唯一标识）
      - children: ReactNode（要分析的子树）
    - 返回: ReactNode（包裹后的子树）
- 使用示例（概念性）
  - 包裹需要分析的组件：`<CommitProbe id="table1"><Table /></CommitProbe>`
  - 在控制台查看提交性能：`[renderProbe] commit table1 update 本次提交耗时 15.2ms`
- 设计要点
  - 使用 Profiler 的 onRender 回调收集提交信息
  - 通过 probeEnabled() 检查探针开关，避免不必要的性能开销
  - 输出格式化的调试信息，便于性能分析

### Store 数据与请求工具
- 职责
  - 初始化数据与请求配置，构建父子依赖关系
  - 提供 getData/setData 在 Store 中读写数据
  - 根据视图配置发起网络请求，格式化并缓存数据，触发子节点请求
  - 集成统一日志系统，在所有关键操作中使用 logger 输出调试信息
- 关键流程
  - initDataAndReq：扫描声明的请求节点，建立 parentIds/childIds 依赖图
  - getData：解析真实路径，优先取数据源，否则回退到 Store 数据
  - setData：根据路径更新 Store 数据
  - StoreReq.send/getReqData：根据 viewId 找到请求配置，调用 NetUtils 获取数据，格式化后存入 Store，并递归触发子请求
- 流程图（getReqData 核心逻辑）

## 性能考量
- 使用 PerfTrackUtils 对热点函数（如 getData、fetchData）进行包装，定期调用 printStats 观察平均耗时与异常率
- 合理拆分请求与数据处理逻辑，减少单次函数执行时长
- 利用 Store 的父子依赖机制批量触发子请求，避免重复请求
- 在网络层设置合理的超时时间与重试策略（可在业务侧扩展）
- 对大数据集进行分页或懒加载，降低内存占用
- 日志性能优化：通过日志级别控制减少不必要的日志输出，生产环境建议使用 warn 或 error 级别
- **渲染性能优化**：
  - 使用 useRenderProbe 定位频繁渲染的组件
  - 通过 createMemoProbe 优化 memo 边界，减少不必要的重渲染
  - 使用 CommitProbe 分析提交性能，识别慢提交
  - 通过 traceStoreWrites 优化数据更新策略，减少不必要的 store 写入
  - 合理使用 React.memo、useMemo、useCallback 等优化手段

## 故障排查指南
- 401 未授权
  - 现象：请求被拒绝，触发错误回调
  - 排查：确认已调用 NetUtils.init，且 Token 已正确设置；必要时调用 handleUnauthorized 跳转登录
- 请求失败
  - 现象：网络错误或响应异常
  - 排查：检查 baseURL、url、params；查看 errorHandler 输出的 code 与 message
- 数据未更新
  - 现象：界面未反映最新数据
  - 排查：确认 setData 路径是否正确；使用 PathUtils.toString 校验路径；检查 Store 中对应键是否存在
- 性能问题
  - 现象：页面卡顿或响应慢
  - 排查：使用 PerfTrackUtils 包装关键函数，调用 printStats 定位瓶颈；优化数据处理逻辑
- 日志相关问题
  - 现象：日志输出不符合预期
  - 排查：检查 VITE_LOG_LEVEL 环境变量配置；使用 getLogLevel() 查询当前日志级别；通过 setLogLevel() 动态调整
  - 现象：生产环境日志过多影响性能
  - 排查：确保生产环境设置合适的日志级别（建议 warn 或 error）；检查是否有调试代码未移除
- **渲染性能问题**
  - 现象：组件频繁重渲染或提交缓慢
  - 排查：使用 useRenderProbe 记录组件执行次数；通过 createMemoProbe 检查 memo 边界；使用 CommitProbe 分析提交性能
  - 现象：数据变更后组件过度更新
  - 排查：使用 traceStoreWrites 追踪数据变更来源；通过 traceStoreNotify 分析 store 通知成本；优化 selector 和数据结构设计

## 附录
- 常见用法速查
  - 初始化网络：在应用启动时调用 NetUtils.init，并实现错误提示
  - 发起请求：使用 NetUtils.get/post 获取数据
  - 读写数据：通过 Store 的 getData/setData 操作状态
  - 性能观测：用 PerfTrackUtils 包装关键函数，调用 printStats 查看统计
  - 日志管理：使用 setLogLevel 设置日志级别，通过 logger.debug/info/warn/error 输出日志
  - **渲染诊断**：使用 useRenderProbe 追踪组件执行，createMemoProbe 优化 memo 边界，CommitProbe 分析提交性能
- 最佳实践
  - 将网络错误集中处理，避免分散在各处
  - 使用 PathUtils 统一管理路径，减少硬编码
  - 对高频调用的函数进行性能埋点，持续优化
  - 使用统一日志系统：避免直接使用 console，通过 logger 统一管理日志输出
  - 合理配置日志级别：开发环境使用 debug，生产环境使用 warn 或 error
  - **合理使用渲染探针**：仅在开发和测试环境开启，生产环境默认关闭以避免性能影响
- 日志级别说明
  - debug：详细的调试信息，仅在开发环境使用
  - info：一般信息，可用于跟踪程序执行流程
  - warn：警告信息，表示潜在问题但不影响程序运行
  - error：错误信息，表示程序执行中出现的问题
  - silent：静默模式，不输出任何日志
- **渲染探针开关说明**
  - 默认关闭：通过 localStorage.setItem('renderProbe', '1') 或 setProbeEnabled(true) 开启
  - 持久化：开关状态保存在 localStorage，刷新后保持
  - 零开销：关闭时仅有一次布尔判断，可长期保留在组件中不摘除
