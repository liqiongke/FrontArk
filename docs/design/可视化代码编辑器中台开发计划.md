## 1. 需求与目标

### 1.1 一句话定位

给当前 monorepo 加一个**本机/局域网运行的中台**：选定任意一个目标工程路径后，把该工程的「页面结构」可视化出来，**支持在界面上直接改结构、改属性、改主题配色**，并且**每一次修改都落到真实源码的对应行**——源码始终是唯一事实来源，编辑器只是它的一个视图。

### 1.2 用户提出的四条硬需求（逐条对齐）

| # | 原始需求 | 本文对应章节 | 实现手段 |
|---|---|---|---|
| 1 | 新增一个项目（package），可自行设置「目标项目路径」 | §5.1 / §9 | 项目注册表 + `ProjectProfile` 探测 |
| 2 | 依据 `apps/demo` 的页面结构，可视化展现并支持修改页面结构 | §5.2 / §5.8 | TS AST 解析 → 语义模型 → 结构画布 |
| 3 | 系统层面：改主题配色；增删改页面结构 | §5.7 / §5.8 | PostCSS token 编辑；视图节点增删移 + 引用一致性 |
| 4 | 页面内部：结构预览图 + 结合数据实时渲染 + 点击跳转代码行 | §5.5 / §5.6 | Vite 预览宿主 + iframe + 元素探针 + 锚点跳转 |
| 5 | 所有属性都支持修改 | §5.3 / §5.4 | 从框架 TS 类型自动生成「编辑元数据」+ 无损局部写回 |
| 6 | 后端 Go，调用 Node 的能力 | §4 / §5.2 | Go 主服务 + Node sidecar（TS Compiler API） |
| 7 | 参考 `blade_and_hearth_idle/editor` 的方案 | §1.3 | 同构分层（server / web / shared），沿用原子写 + `.bak` + mtime 乐观锁 |

### 1.3 从参考项目继承什么、丢弃什么

| 参考项目的做法 | 是否继承 | 说明 |
|---|---|---|
| `server/`（Go）+ `web/`（React）+ `shared/`（schema JSON）三段式 | ✅ 继承 | 目录结构照搬，`start.ps1` 一键起前后端 |
| **唯一事实源是 JSON 数据文件**，页面由 JSON 驱动 | ❌ 丢弃（方向反转） | 本项目的唯一事实源是 **TS 源码**，不是 JSON。所以不能"JSON → 代码生成"，只能是"AST ↔ 代码" |
| 数据文件的原子写：`.bak` 备份 + 临时文件 + `os.Rename` | ✅ 继承 | `store.go:79-130` 的策略逐条复用，只是写的是 `.tsx` 而不是 `.json` |
| mtime 乐观锁（不匹配返 409） | ✅ 继承并加强 | 升级为 **mtime + 内容 sha256 双校验**（TS 文件改一行也会变 mtime，但 sha 能确认"改的是不是我们认知的那份"） |
| `shared/schemas/*.json` 驱动的通用表单 | ✅ 形态继承，来源换掉 | 本项目的 schema 不再手写，而是**从框架的 TS interface 自动生成**（§5.3） |
| Go 只有薄薄一层（读/校验/原子写/静态托管） | ⚠️ 部分调整 | 本项目 Go 稍厚：需要管 Node sidecar 生命周期、预览进程、编辑历史 |
| 默认只绑 `127.0.0.1` | ⚠️ 放宽 | 用户明确要"本地局域网编辑"，所以支持 `-addr 0.0.0.0` + 一次性 Token |

设计必须建立在实际代码事实之上。以下每条都给了依据位置。

### 2.1 仓库结构

```

├── turbo.json               build / dev / dev:mock / lint
├── apps/
```

### 2.2 `apps/demo` 的页面是「声明式四件套」

以 `apps/demo/src/pages/base/table/` 为例：

| 文件 | 类 | 职责 | 依据 |
|---|---|---|---|
| `index.tsx` | — | 只做装配：`<ViewRoot ViewClass={VType} DataClass={Data} HandlerClass={Handler} />` | `base/table/index.tsx:5-7` |
| `data.tsx` | `Data extends DataBase` | 数据节点：`id` / `url` / `keyAttr` / `params` / `dependsOn` / `format` / `retry` | `base/table/data.tsx:8-24`；类型定义 `packages/framework/src/data/interface.ts:4-20` |
| `view.tsx` | `View extends ViewBase<Handler, Data>` | 视图节点：`VProps.Table` / `VProps.Form` / `VProps.Flex` + `getRootId()` | `base/table/view.tsx:12-197` |
| `handler.ts` | `Handler extends HandlerBase` | 命令式逻辑：`getData/setData/getSelectedKeys/post/get` | `base/table/handler.ts:4-52` |

**这正是"高度结构化"的来源**：页面 = 可枚举的类字段 + 可枚举的字面量对象，非常适合 AST 化。

### 2.3 框架提供的运行时枚举 = 天然的"组件/控件注册表"

| 注册表 | 位置 | 内容 |
|---|---|---|
| `ViewTypeMap` | `packages/framework/src/comp/compFactory.ts:17-27` | 7 种 `ViewType` → React 组件：`LayoutFlex` / `LayoutTab` / `LayoutModal` / `LayoutDrawer` / `Table` / `Form` / `Toolbar` |

枚举本体：`ViewType`（`src/comp/view/interface.ts:26-60`）、`Ctrl`（`src/comp/control/interface.ts:32-46`）、`RenderMode`（`src/comp/view/table/interface.ts:47`）、`SummaryType`（同文件 `:195`）、`PathKey`（`src/stores/store/interface.ts:82`）。

**关键发现**：枚举成员上已经写了中文 JSDoc，形如

```30:30:packages/framework/src/comp/view/interface.ts
Table = 'VIEW_TABLE',
```
其上方带 `@name 组件 表格`（`interface.ts:27-30`）。**这可以直接作为可视化面板的中文 label 来源**，不需要再维护一份映射表。

### 2.4 属性体系只有 TS 类型，没有 JSON Schema

- `VProps` 是**纯类型 namespace**（`packages/framework/src/index.ts:56-81`），构建时被完全擦除。
- 各组件属性分散在 `src/comp/view/*/interface.ts(x)`，控件属性在 `src/comp/control/*/interface.tsx`。
- `packages/framework/dist/` **当前不存在**（`index.d.ts` 未构建）→ **不能指望读 `.d.ts`，必须直接解析 `src/**/interface.ts`**。

结论：**编辑器的属性面板必须由「类型 → 元数据」的生成器来喂**（§5.3），否则就要手写 200+ 字段的表单，不可维护。

## 3. 需求澄清与范围

### 3.1 对「在 packages 增加一个新的项目」的理解（假设）

原文：「在页面的『packages』增加一个新的项目，这个项目需要自己设置项目的路径」。

本设计按如下理解落地，**若与实际意图不符请指出**：

- **A（采纳）**：在 workspace 的 `packages/` 下新增一个项目 `packages/studio/`，它自身即中台（前端 + Go 服务 + Node sidecar）；
- **B（采纳）**：该中台有一个「项目注册表」，用户可以为它**设置任意目标工程的绝对路径**（默认预填本仓库的 `apps/demo`）；设置完成后，中台按 `apps/demo` 的页面结构去解析并可视化**那个目标工程**。
- 因此「设置项目路径」= 中台编辑的**对象工程**，而**不是**中台自己的工程目录。

### 3.2 结构化识别分级

不是所有页面都按四件套写。识别分三级，降级不报错：

| 级别 | 判据 | 能力 |
|---|---|---|
| **L1 框架页面** | 目录含 `index.tsx`，且其 JSX 装配了 `ViewRoot`，导入解析出 Data/View/Handler 三个类 | 全能力：结构树 / 预览 / 属性编辑 / 结构编辑 / 跳转 |
| **L2 普通 React 页面** | 有 `index.tsx` 但无 `ViewRoot` 装配 | 只读：路由候选 + 源码跳转 + 预览 iframe |
| **L3 无法静态确定** | 重导出 / 动态工厂 / 复杂装配 | 标记「部分识别」，只给导航与源码打开 |

### 3.3 明确不做（首版）

- ❌ 不做「拖拽即绘画」的通用低代码设计器（只做**已有源码节点的重排/增删**）；
- ❌ 不引入与源码双向同步的第二套业务配置库（源码是唯一事实来源）；
- ❌ 不把 Handler 的函数体/JSX/动态表达式转成表单（只读 + 跳转）；
- ❌ 不改写目标工程的 `node_modules`、不自动 `pnpm install`；
- ❌ 不自动写后端菜单接口（只提示影响）。

## 4. 总体架构

### 4.1 为什么是「Go + Node 双进程」

用户要求「后端是 Go，调用 Node 的一些方法」。这不是迁就，而是**正确的分工**：

- **TS/TSX 的 AST 生态只在 Node 侧成熟**（TypeScript Compiler API / ts-morph / postcss / jsonc-parser）。在 Go 里手写 TS 解析器是自杀。
- **进程/文件/HTTP/静态托管/生命周期**在 Go 侧更稳、单二进制、无运行时依赖，且与参考项目的工程习惯一致。

所以：

- **Go 主服务**是唯一的对外 HTTP 入口、唯一的**写盘者**、唯一的前端静态托管者；
- **Node sidecar** 是纯计算进程，**无状态、无端口、不允许直接写盘**——它只接收源码快照、返回 `TextEdit` 列表。这样即使 sidecar 被恶意输入打挂，也不可能碰坏源码。

### 4.3 为什么 Go 是唯一的写盘者

沿用并强化参考项目 `store.go` 的策略（`editor/server/store.go:79-130`）：

1. 校验通过才写；
2. 先备份 `<name>.bak`（保留最近 1 份 + 可选历史目录）；
3. 写入同目录 `.tmp-*` → `tmp.Sync()` → `os.Rename` 原子替换；
4. 编码与换行策略：**保留原文件的 BOM / CRLF-LF / 末尾换行**（参考项目写 JSON 可以统一，我们写 TS 必须保留原样，否则整文件 diff）。

sidecar 只回 `{file, start, end, newText}`，Go 自己读文件、应用区间、校验区间不重叠且落在文件长度内、再写。

### 4.4 技术选型

| 领域 | 选择 | 理由 / 边界 |
|---|---|---|
| Go 服务 | Go 1.24+，标准库 `net/http`（沿用参考项目 Go 1.24 / 无框架） | 零依赖、单二进制 |
| 前端 | React 19 + Vite 6 + Tailwind v4 + shadcn/ui | 与 `@jl/framework`、参考项目 `editor/web` 完全一致 |
| 前端外壳 | **优先复用 `@jl/framework`** 的 `LayoutFlex/Tab/Table/Form` + `NetUtils` + `notify` | 吃自己的狗粮；见 §10.1 需要的 3 处最小增强 |
| TS 解析 | `typescript` Compiler API（**首选**）/ `ts-morph`（便利封装） | 不引入 babel，避免两套 AST 语义 |
| CSS 解析 | `postcss` + `postcss-value-parser` | 保留注释与格式 |
| 颜色 | `culori`（OKLCH ⇄ sRGB ⇄ HEX） | 框架 token 是 OKLCH |
| 预览 | Vite Node API（`createServer`）自建预览宿主 | 见 §5.5 |
| 进程通信 | stdio NDJSON JSON-RPC 2.0 | 无端口、无鉴权面、生命周期由 Go 掌控 |
| 持久化 | 项目注册表 + 编辑历史存 `os.UserConfigDir()/frontark-studio/` | **不污染目标工程与 git** |
| 测试 | Node `node:test` + vitest（前端）；Go `testing` | 与现有 `apps/demo/tests` 风格一致 |

## 5. 核心技术方案

### 5.1 项目注册与「目标项目路径」设置

#### 5.1.1 数据模型

```ts
interface ProjectProfile {
  id: string;              // 稳定 id，如 'demo' | sha1(rootPath).slice(0,8)
  name: string;            // 展示名（默认取 package.json.name，取不到则取目录名）
  rootPath: string;        // 绝对路径（Windows 反斜杠归一为 /）
  kind: 'frontark' | 'react' | 'unknown';   // 是否依赖 @jl/framework + 有 src/pages
  scannedAt: string;
  // 以下全部由探测得出，允许用户在「项目设置」里覆盖：
  overrides: {
    pagesDir?: string;         // 默认 <root>/src/pages
    aliases?: Record<string,string>;  // 默认从 tsconfig*.json 的 paths 抽
    workspaceRoot?: string;    // monorepo 根（用于解析 @jl/framework）
    frameworkAliasTo?: string; // 默认 <workspaceRoot>/packages/framework/src
    devServer?: { script: string; port: number };
    mockBaseUrl?: string;      // 预览内数据请求 baseURL
    themeFiles?: string[];     // 额外参与配色编辑的 CSS 文件
    entryHtml?: string;
  };
}
```

#### 5.1.2 探测（`analyzer` 的 `project.probe`）

给定一个路径，按顺序产出 `ProjectProfile`：

1. 必须是目录，且**存在** `package.json`（否则拒绝）；
2. 读 `package.json` → `name`，`dependencies/devDependencies` 是否含 `@jl/framework`；
3. 找 monorepo 根：向上找 `pnpm-workspace.yaml` / `package.json.workspaces`；
4. 存在 `src/pages`（或 `overrides.pagesDir`）→ `kind` 升级；
5. 读 `tsconfig*.json` 的 `compilerOptions.paths`（JSONC 解析，保留注释）→ `aliases`；
6. 读 `vite.config.ts` 静态可识别部分 → 页面目录、端口（沿用既有文档 `:458` 的"只做静态识别、复杂分支保留源码"原则）；
7. 枚举 `src/pages/**/index.tsx` 得到路由候选列表（**不启动应用、不 import 业务模块**）。

> **安全前置**：注册 = 把该目录加入**白名单**，后续所有文件操作都必须落在白名单根之内（`filepath.EvalSymlinks` 解析后再比对，防 junction 逃逸）。

#### 5.1.3 持久化与作用域

- 默认写 `os.UserConfigDir()/frontark-studio/projects.json`（Windows: `%APPDATA%\frontark-studio\`）；

### 5.2 源码解析：AST → 语义模型

#### 5.2.1 解析流水线

```
page.route 候选            ──┐
                             │
index.tsx 装配分析           │  ① 找 ViewRoot JSX；解析 ViewClass/DataClass/HandlerClass
  → {viewFile, dataFile,    │     的**实际导入来源**（支持别名、import type、.ts/.tsx）
     handlerFile}           │
                             │
view.tsx  → SourceFile AST   │  ② 收集 ClassDeclaration 的 PropertyDeclaration：
  → 每个视图节点一个对象      │     - 初始化器是 ObjectLiteral → 取 type 字段判定 ViewType
                             │     - 递归 items / searchItems / toolList / items[] 子节点
                             │     - 记录每个字段的锚点 + 值分类 + 可编辑性
                             │
data.tsx  → 数据节点列表     │  ③ 同理，按 DataProps 字段枚举
                             │
handler.ts → 方法清单        │  ④ 只收集名字 + 锚点 + JSDoc，函数体一律只读
                             │
引用索引                     │  ⑤ 扫 layout.items / getRootId / Tab.viewId / Modal.viewId /
                             │     Drawer.viewId / dataId / path 中的 @Active:、@Row:、
                             │     DataBase.active(...)、this.handler.xxx
```

#### 5.2.2 语义模型（本设计的核心数据结构）

```ts
type NodeKind =
  | 'project' | 'page' | 'dataNode' | 'dataParam'
  | 'view' | 'viewItem' | 'ctrl' | 'handlerMethod'
  | 'theme' | 'themeToken' | 'sourceOnly';

type Editability =
  | 'literal'      // 字符串/数字/布尔/null：可直接改
  | 'literal-struct' // 对象/数组字面量：结构内可增删改
  | 'enum-ref'     // VType.Table / Ctrl.Select：选择器改，写回枚举成员访问表达式
  | 'member-ref'   // this.data.mainTable.id：引用选择器改，写回成员链路
  | 'call-ref'     // DataBase.active(this.table1.id)：专用选择器改，写回调用表达式
  | 'module-ref'   // items: CATEGORY_OPTIONS：只跳声明，不改（避免影响多消费者）
  | 'handler-ref'  // this.handler.onSetData：方法选择器改
  | 'expr'         // 箭头函数 / 模板串 / 展开：只读
  | 'source-only'; // 完全只读

interface SourceAnchor {
  file: string;        // 相对 project.rootPath
  start: number;       // 字符偏移
  end: number;
  line: number;        // 1-based，供跳转
  column: number;
  endLine: number;
  endColumn: number;
  hash: string;        // 该区间文本的 sha1（apply 时校验漂移）
}

interface SemanticNode {
  id: string;          // 快照内稳定 id：`page:base/table#view:table1/items[2]/width`
  kind: NodeKind;
  label: string;       // 中文，优先取 JSDoc @name / title 字段 / 元数据 label
  type?: string;       // ViewType 或 Ctrl 的值
  memberName?: string; // TS 成员名（table1 / mainTable / onPrintData）
  declaredId?: string; // 视图/数据节点 id（其实是一回事，单独列出便于重命名）
  editability: Editability;
  value?: unknown;     // 仅 literal / literal-struct 有
  ref?: { kind: 'view'|'data'|'handler'|'module'|'active'|'row'; target: string };
  anchor: SourceAnchor;
  children: string[];  // 子节点 id
  issues: string[];    // 该节点上的诊断 code
}
```

**约束（来自既有文档 §7.3 的教训，必须遵守）**：

- `id` 不能直接用 `field` 或业务 id —— `base/table/view.tsx` 里 `field` 是允许重复的 UI 用法（表单展示同一字段用不同控件），用 `field` 当节点 key 会导致误改。
- 遇到**对象展开 / 计算属性 / 重复属性**时，必须评估"是否覆盖目标字段"；无法确定覆盖顺序 → 该字段关闭写入，降级 `source-only`。

#### 5.2.3 增量与缓存

- **按需解析**：选中页面才做完整解析；项目列表阶段只读文件元信息（沿用既有文档 §6.3）。
- 缓存 key = `file` + `sha256(内容)`；`fs.watch`（Go 侧）感知外部改动 → 通过 SSE 通知前端失效。
- 变更合并窗口 **200ms**；过期结果直接丢弃。
- 解析在 sidecar 内用 `worker_threads` 做，避免阻塞 stdio 响应（大工程 ≤5s 冷索引为验收目标，见 §12）。

自动生成拿不到的信息，用一层薄的 overrides 补：

| 补充项 | 说明 | 例子 |
|---|---|---|
| `editor` | 用哪个控件 | `color`、`dPath`、`refSelect`、`code` |

#### 5.3.3 版本漂移防护

- 生成物里写 `.fingerprint`（framework 相关文件 hash 列表）；
- Studio 启动时对比，不匹配 → **横幅警告 + 一键重新生成**，并对新字段降级为只读（绝不用过期元数据写入）；
- 生成脚本纳入 `pnpm -F studio meta:gen`，并建议在 CI 里断言 fingerprint 一致。

#### 5.3.4 「所有属性」的覆盖率承诺（诚实版）

| 类别 | 覆盖 | 手段 |
|---|---|---|
| 字面量（string/number/bool/null） | ✅ 100% | 直接替换区间 |
| 字面量对象/数组（含嵌套） | ✅ 结构内增删改 | 结构化编辑器 |
| 枚举成员引用 | ✅ | 选择器 + 写回 `VType.Xxx` |
| `this.data.X.id` / `this.viewY.id` | ✅ | 引用选择器 + 写回成员链路 |
| `DataBase.active(...)` | ✅ | 专用"绑定方式"选择器 |
| `this.handler.method` | ✅ 改引用；方法体只读 | 方法选择器 |
| 模块级常量引用（`CATEGORY_OPTIONS`） | ⚠️ 只跳转 | 影响多消费者，首版不改 |
| 箭头函数 / JSX / 模板串 / 展开 | ⚠️ 只读 | 展示源码片段 + 跳转 |
| 继承自框架基类但未声明的属性 | ✅（来自类型提取） | 生成器已含 `& Base` 合并 |
| 目标工程自定义扩展字段 | ⚠️ 只读 + 可手动加 override | 未知字段保留原样 |

**明确不做虚假承诺**：凡是无法静态确定语义的，一律 `source-only`，并给"在源码中打开"入口。

### 5.4 无损编辑与两阶段提交

#### 5.4.1 编辑链路

```
① 前端提交意图（不是文本、不是路径、不是范围）
   POST /api/edit/plan  { projectId, snapshotId, nodeId, op:{kind,path,value} }

② Go 校验：会话 / 项目白名单 / 值类型与大小 / op 白名单
   → 转发 analyzer:  edit.plan

③ analyzer：
   · 取该页面的当前解析快照（含每节点 anchor.hash）
   · 校验 nodeId 与 anchor 未漂移（hash 一致）
   · 生成最小 TextEdit 列表 [{file,start,end,newText}]（**不重排、不格式化**）
   · 在内存里把 edits 应用到文本 → 重新 parse → 做一次语法自检（可 parse 且有错误则拒绝）
   · 返回 { planId, edits, preview:{before,after}, warnings }

④ 前端展示 diff（可开关）→ POST /api/edit/apply { planId }
   默认对"低风险字段"（title/width/field 之类的标量）跳过确认，直接 apply

⑤ Go：再次校验每个文件的 sha256 未变 → 读取 → 应用区间 → 原子写（.bak）→
   写历史 → SSE 广播 {type:'files-changed', files:[...]}

⑥ 前端收到 SSE → 重新解析该页面 → 刷新结构树 / 属性面板 / 预览宿主 HMR 自动更新
```

#### 5.4.2 无损写回的硬规则

| 规则 | 说明 |
|---|---|
| **永不整体 print 文件** | 只替换目标字符区间，其余字节不动 |
| 保留引号风格 | 原用单引号就写单引号（除非新值含单引号则转义，并 warn） |
| 保留包裹语法 | `'table' as const` 只改 `'table'` 这一段；`satisfies DataProps` 完全不动 |
| 保留换行风格 | 检测文件 CRLF/LF，新增文本沿用 |
| 保留缩进 | 从目标行探测缩进宽度与 tab/space，新增项对齐 |
| 保留 BOM | 读时记录，写时写回 |
| 保留尾随逗号风格 | 从同级容器探测 |
| 保留注释与空行 | 区间替换天然保留 |
| 新增项插入位置 | 追加到容器末尾（`items` 数组的 `]` 前），并复制同级分隔风格 |
| 数组删除 | 连同**前一个或后一个**逗号一起删，不留空行碎屑 |

#### 5.4.3 并发与失败

沿用既有文档 §8.2：

- 文档版本 / mtime / sha 任一变化 → 旧 plan **失效**，返回 `409 stale-plan`，前端提示"源码已被外部修改，已刷新"；
- 同一项目的编辑**串行**（Go 侧 per-project mutex）；
- `apply` 是"先校验后写"，**不做跨文件事务承诺**；多文件编辑（如重命名 viewId）按文件顺序写，失败即停止并**报告已改与未改的清单**，不回滚恢复（避免用旧内容覆盖）；
- **不使用** `applyEdit` 式的"全文件重写 + 覆盖"。

#### 5.4.4 撤销 / 重做

- 每一条已应用的 edit 记录为一条 `EditRecord { id, projectId, files, reverseEdits, forwardEdits, ts, plan }`；
- 历史存内存 + 落盘 `UserConfigDir/frontark-studio/history/<projectId>/`（保留最近 200 条）；
- 撤销 = 用 `reverseEdits` 走同一条 apply 链路（同样校验 sha）；重做同理；
- 前端 `Ctrl+Z / Ctrl+Shift+Z`，与参考项目一致（`editor/README.md:49`）。

### 5.5 页面预览：结构预览图 + 数据实时渲染

#### 5.5.1 方案对比与选择

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. iframe 指向目标项目 dev server** | Studio 起 `pnpm dev`，iframe 指向 `http://localhost:7000/base/table` | 100% 真实、零适配 | 每次都要跑整个应用；无法元素级联动；占端口 | 作为「**运行态预览**」补充模式（P2） |
| **B. 自建预览宿主（Vite Node API）** | Studio 内建一个小 React 宿主，用 `/@fs/` 动态导入目标页面文件 | 不用启动目标应用；可注入探针；启动 ~1s | 需要合并别名/依赖去重 | ✅ **首选（P1）** |
| **C. 在 Studio 前端进程内直接 import 目标文件** | 编译期静态导入 | 简单 | 跨工程不可行、无法热更 | ❌ |

#### 5.5.2 预览宿主设计

`packages/studio/preview/`（一个极小的 Vite 工程）：

```tsx

  await import(/* @vite-ignore */ '/@fs/' + params.get('page'));

createRoot(document.getElementById('root')!).render(
  <StrictMode>

```


#### 5.5.3 「结合数据实时渲染」的三种数据源

| 模式 | 做法 | 适用 |
|---|---|---|
| `mock`（默认） | 预览宿主的 `NetUtils.init({baseURL: http://127.0.0.1:3001/api})`，直接吃 `packages/mock` | 本仓库 demo；开箱即用 |

#### 5.5.4 元素探针：预览里点元素 → 定位语义节点

复用并扩展 `packages/framework/src/utils/renderProbe.ts`（已存在）：

- **框架侧最小增强**：当 `window.__FRONTARK_STUDIO__` 为真时，`CompFactory` / `CtrlFactory` / 表格列渲染 / 表单 item 渲染处，给根元素附加

### 5.7 主题配色编辑

#### 5.7.1 可编辑对象

| 文件 | 内容 | 默认是否纳入 |
|---|---|---|
| `packages/framework/src/ui/styles/theme.css` | `:root` / `.dark` 的 OKLCH token（`--background/--primary/--surface/--table-head/--row-hover/--selected/--divider` …）；`[data-density]` | ✅（框架 token，全站生效） |

#### 5.7.2 编辑链路

```
postcss.parse(css) → 遍历 decl，记录 { selector, prop, value, anchor }
  → 前端渲染「token 分组面板」（按语义分组：底色 / 文字 / 主色 / 边框 / 表格 / 侧栏）
  → 用户改色（色轮 / HEX / OKLCH 三输入联动，culori 换算）
  → 生成 TextEdit（只替换那一个 value 区间，保留注释与格式）
  → 走 §5.4 的同一条两阶段提交链路
```

#### 5.7.3 实时预览

- 预览 iframe 与 Studio 之间用 `postMessage({type:'theme-preview', vars:{...}})`；
- iframe 内把变量写到一张 `<style id="studio-preview-theme">:root{...}</style>`，**不写文件**；
- 用户点「保存」才落盘 —— 这是"实时预览 / 显式保存"的分离，与参考项目"编辑 → 保存 JSON"的节奏一致。

#### 5.7.4 校验与辅助

| 校验 | 级别 |
|---|---|
| 颜色格式非法（不是 OKLCH/HEX/rgb） | error（阻断保存） |
| 必需 token 缺失（如删掉 `--background`） | error |
| `foreground` 与 `background` 对比度 < 4.5:1 | warning（WCAG AA 提示，不阻断） |
| `--table-head` / `--row-hover` 与 `--surface` 差异 < 阈值 | warning（表头看不出分界） |
| 新增 token 未在 `@theme inline` 暴露 | info（提示无法用 Tailwind 类引用） |

浅色 `.dark` 双份编辑：支持「锁定两套同步改」「分别编辑」「由浅色推导深色（明度反转）」三种模式。

#### 5.7.5 预设与导出

- 「另存为主题预设」→ 生成 `<target>/src/theme/<name>.css` + 在 `index.css` 追加 `@import`（**结构修改需用户确认**，因为改了项目文件组织）；
- 「导出 JSON 调色板」→ 给设计同学用。

### 5.8 结构编辑（增删改）

#### 5.8.1 支持的原子操作

| 操作 | 语义 | 落盘改动 |
|---|---|---|
| 新增视图节点 | 复制某 `VProps.X` 模板，分配新 id | `view.tsx` 新增类字段；`layout.items` 追加 id |
| 删除视图节点 | 移除类字段 | 删字段 + 从所有 `items` / `viewId` 引用中摘除（**引用未清空则阻断**，除非强制） |
| 重排 | 改 `items` 顺序 | 数组元素区间移动 |
| 跨容器移动 | 从 A 的 `items` 移到 B | 两处数组删/插 |
| 改 id | 语义重命名（视图 id） | 见 §5.8.2 |
| 新增数据节点 | 复制 `DataProps` 模板 | `data.tsx` 新增字段 + 维护 `DataNodeId` 联合类型（`base/table/data.tsx:31`） |
| 新增页面 | 生成四件套 + 目录 | `src/pages/<route>/` 下 4 个文件 + 提示菜单未登记 |

#### 5.8.2 语义重命名（最危险的操作）

改一个「视图 id」会牵动（以 `table1` 为例）：

1. `view.tsx` 的类字段名 `table1`；
2. `table1` 内部的 `id: 'table1'`；
3. `layout.items: [..., this.table1.id]`；
4. 其它视图里的 `path: [DataBase.active(this.table1.id)]`；
5. `Tab.items[].viewId`、`Modal.viewId`、`Drawer.viewId`；
6. `handler.ts` 里的 `getSelectedKeys('table1')` / `setSelectedKeys('table1', ...)`（字符串常量！）；
7. `data.tsx` 导出的 `DataNodeId` 联合类型（若改的是数据节点）。

**策略**：引用索引先算出完整"待改清单"，**清单里出现无法静态确认的引用（字符串拼接、变量传递）→ 禁用一键重命名**，只做单点修改并高亮未覆盖项。绝不全局字符串替换（既有文档 §8.3 的结论）。

#### 5.8.3 一致性校验（阻断保存）

- `layout.items` 中每个 id 必须能在同类里找到字段（`this.<id>.id` 或字面量 id）→ 否则 `ST002`；
- `getRootId()` 返回的 id 必须存在 → `ST007`；
- `Tab/Modal/Drawer.viewId` 必须指向存在的视图 id → `ST003`；
- `dataId` 必须指向存在的 `Data` 节点 id → `ST005`。

### 5.9 领域诊断规则

沿用既有文档 §11 的 `FA001–FA010`（页面装配 / 重复 ID / 绑定目标 / `@Active` 类别 / handler 方法 / 根视图 / 环境变量 / 敏感配置 / 路由影响 / 适配器不兼容），新增 Studio 专属：

| 规则 | 级别 | 条件 |
|---|---|---|
| `ST001` 视图 id 重复或缺 `id` 字段 | error | 同页面内 `id` 字面量重复 |
| `ST002` 布局引用了不存在的视图 id | error | layout.items 中 id 无对应节点 |
| `ST003` Tab/Modal/Drawer 的 viewId 悬空 | error | 静态可确定时 |
| `ST004` `@Active:` 指向数据节点而非视图 id | error | 与视图 id 集合比对 |
| `ST005` `dataId` 指向不存在的 Data 节点 | error | — |
| `ST006` `this.handler.xxx` 方法不存在 | error | 解析本类 + 基类（不能只查本类） |
| `ST007` `getRootId()` 返回 id 不存在 | error | — |
| `ST008` 主题 token 缺失 / 非法 / 对比度不足 | error / warning | §5.7.4 |
| `ST009` 预览宿主加载失败（导入报错） | error | 捕获 Vite 错误，展示堆栈 + 定位到报错文件行 |
| `ST010` 编辑元数据与框架源码漂移 | warning | fingerprint 不匹配 |
| `ST011` 新增页面未登记后端菜单 | info | 仅提示，不报错 |

问题面板支持"点击跳转"（复用 §5.6 的锚点）。

所有返回统一信封：

```json
{ "ok": true, "data": {}, "issues": [], "meta": { "sha": "...", "mtime": "..." } }
```

### 6.2 Go ↔ Node sidecar 协议（JSON-RPC 2.0 / NDJSON / stdio）

| 方法 | 入参 | 出参 |
|---|---|---|
| `health` | — | `{ version, tsVersion }` |
| `project.probe` | `{ rootPath, overrides }` | `ProjectProfile` |
| `pages.list` | `{ rootPath, profile }` | `PageCandidate[]` |
| `page.analyze` | `{ rootPath, route, fileShas }` | `{ nodes, issues, anchors, fileShas }` |
| `meta.generate` | `{ frameworkRoot }` | `{ meta, fingerprint }` |
| `edit.plan` | `{ rootPath, snapshotId, nodeId, op, fileContents }` | `{ planId, edits, preview, warnings }` |
| `edit.verify` | `{ edits, fileContents }` | `{ ok, syntaxIssues }` |
| `refs.index` | `{ rootPath, pageGlobs }` | `{ refs }` |
| `theme.parse` | `{ files }` | `{ groups, tokens, anchors }` |
| `theme.plan` | `{ file, selector, token, value }` | `{ edits }` |
| `refactor.rename` | `{ rootPath, kind, from, to }` | `{ edits, uncovered[] }` |

约定：

- **sidecar 不读文件系统**（除 `project.probe` / `pages.list` 的必要枚举），源码内容一律由 Go 传进来 → 保证"Go 是唯一接触磁盘的角色"，也让 sidecar 可以在 worker 里无副作用地跑；
- 每个请求带 `timeout`，Go 侧 30s 超时后重启 sidecar；
- sidecar 崩溃自动重启（指数退避，最多 5 次），并在 `/api/health` 报降级状态。

### 6.3 前端状态与事件

- SSE 单连接，事件类型：`files-changed` / `plan-applied` / `diagnostics` / `preview-status` / `sidecar-status`；
- 前端用 zustand（框架 `storeBase` 也基于 zustand）保存 `projects / currentPage / semanticTree / selectedNode / pendingPlan / history`；
- 变更合并 200ms，过期解析结果丢弃（§5.2.3）。

### 7.4 复用 `@jl/framework` 的程度与所需最小增强

**推荐**：Studio 前端用 `@jl/framework` 的 **UI 层**（`packages/framework/src/ui` 的 shadcn 组件 + `theme.css`）和**工具层**（`NetUtils` / `logger` / `notify` / `ViewPathUtils`），布局用 `LayoutFlex` + `LayoutTab`。

需要向框架提 3 个**最小、向后兼容**的增强（都属于 P1，可延后）：

| 增强 | 位置 | 内容 | 影响 |
|---|---|---|---|
| E1 视图注册表可扩展 | `compFactory.ts:17` / `ctrlFactory.ts:19` | 增加 `registerViewType(type, comp)` / `registerCtrlType(type, comp)`（不改默认表） | 让 Studio 能插入自定义控件（锚点徽标、引用选择器） |
| E2 元素探针 | `compFactory.ts` / `renderProbe.ts:1` | 当 `window.__FRONTARK_STUDIO__` 为真时附加 `data-fa-*` 属性 | 生产构建零成本（opt-in） |
| E3 表格/表单 item 级锚点 | `view/table/viewTable.tsx` / `view/form/viewForm.tsx` | 同上，附加到 `<th>` / item 容器 | 支持"选中某一列" |

**若不接受框架改动**：Studio 用纯 React + shadcn 自建外壳，仅复用框架的 `theme.css` 与 `NetUtils`（与参考项目 `editor/web` 完全一致）。此时 E2 改为"预览宿主内用 `MutationObserver` + 启发式推断"，可靠性下降，但功能不阻塞。

## 10. 安全、并发与失败处理

### 10.1 边界

| 项 | 策略 |
|---|---|
| 监听地址 | 默认 `127.0.0.1:8788`；`-addr 0.0.0.0:8788` 才对外，且**必须**设置 `-token`（首启随机生成并打印） |
| 鉴权 | 局域网模式下所有 `/api/*` 需 `Authorization: Bearer <token>`；前端把 token 存 `sessionStorage` |
| 路径边界 | 只能操作已注册项目根内的文件；`filepath.EvalSymlinks` 后比对前缀；拒绝 `..` / 绝对路径 / UNC 逃逸 |
| 文件白名单 | 只允许写 `*.ts/tsx/js/jsx/json/css`；`node_modules` / `dist` / `.git` / 二进制一律拒绝 |
| 大小上限 | 单文件 > 1 MiB 不做 AST，降级为只读源码打开 |
| 敏感文件 | `.env*`、`src-tauri/capabilities/*`、签名材料：只读 + 值掩码 |
| 不执行目标工程代码 | 解析全程静态；预览宿主是**独立进程**，且"启动预览"需用户显式确认 |
| 不落盘敏感值 | 远端 Token 只存内存；历史记录不写环境变量值；源码正文不进持久缓存 |
| 外部进程 | 仅白名单：`code -g`、`pnpm`（预览）、`node`（sidecar）；全部参数数组化，不拼 shell 字符串 |

### 10.2 并发

- per-project mutex：同一项目的 plan/apply/undo 串行；
- sidecar 请求带 `planId` 幂等键，重复 apply 直接返回上次结果；
- 文件被外部修改 → `409 stale-plan` + `files-changed` SSE；
- 预览宿主的 HMR 由 Vite 自己处理；Go 只广播"文件已变"，不干预。

### 10.3 失败降级矩阵

| 失败 | 表现 | 降级 |
|---|---|---|
| sidecar 起不来（无 Node） | 启动即报错，`/api/health` 显示 `analyzer: down` | 中台只提供"项目浏览 + 只读源码"，禁用全部编辑 |
| sidecar 崩溃 | 当前操作失败并提示 | 自动重启（退避，最多 5 次），重启后要求手动刷新页面 |
| 预览宿主失败 | 中栏显示错误 + Vite 报错栈 | 切换到「结构画布」视图，功能不阻塞 |
| 页面是 L2/L3 | 左栏标记 | 只读源码 + iframe 预览（若可） |
| 元数据漂移 | 顶部横幅 | 新字段只读；提供"重新生成元数据"按钮 |
| 目标工程 TS 语法错误 | 解析返回 `syntaxIssues` | 该文件只读 + 展示错误行 |

## 13. 风险与决策边界

| 风险 | 应对 |
|---|---|
| 框架类型没有 JSON Schema，元数据靠生成 | 生成器 + fingerprint 漂移检测 + 未知字段只读；生成失败不阻塞导航 |
| TS 表达式无法静态求值 | 明确"可编辑子集"（§5.3.4），超出即 `source-only`，**绝不运行求值** |
| 写回破坏源码 | 区间替换 + 内存重解析自检 + sha 校验 + 仅 1 份 `.bak` + 历史 + 撤销 |
| 语义重命名漏改引用 | 引用索引 + 未覆盖清单 + 禁止全局字符串替换 + 无法确认时禁用一键 |
| 预览宿主对目标工程不兼容（特殊插件/别名/环境变量） | 提供 `overrides.aliases / pagesDir / entryHtml` 手工兜底；再不行降级为 iframe 直连 dev server；再不行只做结构画布 |
| 目标工程规模大导致解析慢 | 按需解析 + worker + 缓存 + 取消 + 两层文件视图 |
| 框架接口演进 | 适配器特征检测 + 类型指纹 + fixture 回归；不依赖 semver（当前 0.0.0） |
| 局域网暴露可写接口 | 默认只绑本机；对外必须 Token；写入仍受项目白名单约束 |
| 预览启动等于执行目标工程依赖 | 显式确认 + 独立进程 + 可随时停止 + 不自动 `install` |
| Studio 自身变成第二套业务框架 | 只用现有源码结构，不引入 studio 专用 DSL；不支持任何"必须先迁移代码"的能力 |

**默认边界**：内部团队使用、本机或可信局域网、Windows 优先（可用 macOS/Linux）、只编辑本仓库这类 FrontArk 工程。

## 14. 验收剧本（以 `apps/demo/src/pages/base/table` 为样板）

1. 注册 `d:/workspace/web/apps/demo`，显示包名 `web`、9 个页面候选、别名与 mock 地址。
2. 打开 `/base/table`：中栏渲染出真实表格（含分页、统计行、搜索面板），数据来自 `packages/mock`。
3. 在预览里点「价格」列头 → 右栏自动选中 `table1 / items[2] / title`。
4. 点该节点的「⌖」→ 源码 Tab 定位到 `apps/demo/src/pages/base/table/view.tsx:77`。
5. 把「价格」改成「单价」并保存 → `git diff` 只有 `view.tsx` 第 77 行一处变化。
6. 把 `renderMode` 从 `Subscription` 切到 `Record` → 写回 `RenderMode.Record` 枚举引用，格式不变。
7. 新增一列「备注」→ 插入到 `items` 末尾，缩进与尾随逗号与同级一致。
8. 删除「颜色」列 → 引用检查通过 → 数组元素与逗号一并干净移除。
9. 把 `table1` 重命名为 `mainTable` → 7 处引用全部更新；`layout.items` 与 `form1.path` 的 `DataBase.active(...)` 正确；`handler.ts` 的 `getSelectedKeys('table1')` 一并更新。
10. 改 `--primary` 为品牌蓝 → 预览即时变色 → 保存后仅 `theme.css` 1 行变化；`--primary-foreground` 对比度不足时给出告警。
11. 手动在编辑器里改动 `view.tsx` 并保存，再点 Studio 的「保存」→ 返回 409 并提示已刷新，**不覆盖**用户改动。
12. 撤销第 9 步 → 全部引用与字段名还原，`git diff` 为空。
13. 关掉 mock 服务 → 预览显示数据请求失败但结构完整；中台不崩。
14. 以 `-addr 0.0.0.0 -token xxx` 启动，另一台机器访问：无 token 返回 401，带 token 可只读；写入需再次确认。
