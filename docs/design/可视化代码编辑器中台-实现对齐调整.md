## 1. 安全批次

### 1.1 `-addr :8788` 绕过强制 Token（第二轮发现的高危回归）

Go 的 `net.ListenAndServe(":8788")` 中空 host 等价于 **0.0.0.0（监听所有网卡）**，但原 `isLocalAddr` 在 `host == ""` 时返回 `true` → 不触发 Fatal、不要求 Token，**局域网内任何人无需凭证即可读写源码**。

**修复**（`server/main.go`）：

```go
if host == "localhost" {
    return true
}
// 空 host（":8788"）等价于 0.0.0.0，会监听所有网卡 —— 绝不能当成"本机"，
// 否则 `-addr :8788` 就绕过了「对外必须提供 -token」的检查。
if host == "" {
    return false
}
```

同时把安全校验**前移到 sidecar 启动之前**（`Fatalf` 走 `os.Exit`，`defer` 不会执行，原来会留下孤儿 Node 进程），并在 `ListenAndServe` 失败时显式 `sidecar.Close()`；对外监听时打印醒目警告。

**测试**：`security_test.go` 的 `TestIsLocalAddrTreatsWildcardBindAsPublic`（`":8788"` / `"0.0.0.0:8788"` / `"192.168.x.x"` 全部必须判为非本机）。

### 1.2 CSRF：浏览器的「简单请求」不触发预检

`withCORS` 对跨站简单请求（`text/plain`、form）**没有任何约束力**，而回环地址恰好免 Token —— 任意本机网页都能用 `fetch` 打 `POST /api/open`、`POST /api/projects`。

**修复**（`server/api.go`）：在写请求唯一的入口 `decodeBody` 里加两道校验：

```go
func checkWriteSource(w http.ResponseWriter, r *http.Request) bool {
	if site := r.Header.Get("Sec-Fetch-Site"); site != "" &&
		site != "same-origin" && site != "same-site" && site != "none" {
		writeErr(w, http.StatusForbidden, "拒绝跨站请求（CSRF 防护）")
		return false
	}
	if origin := r.Header.Get("Origin"); origin != "" && !localOrigin(origin) {
		writeErr(w, http.StatusForbidden, "拒绝来自其它站点的请求（CSRF 防护）")
		return false
	}
	return true
}
```

外加 Content-Type 收紧（只接受 `application/json`，否则 415）。`localOrigin` 与 `withCORS` 的白名单同口径（localhost / 回环 IP 任意端口），所以 Vite dev server（5174）、预览宿主（7099）、同源 SPA 都不受影响。7 个写接口全部经 `decodeBody`，覆盖面完整。

**测试**：`TestCheckWriteSourceBlocksCrossSite`（6 个用例）+ smoke 脚本新增「跨站 Origin 被拒」「非 JSON Content-Type 被拒」两条断言。

### 1.3 Windows `cmd /c` 不转义元字符

`os/exec` 的 Windows 参数转义只处理空格与引号，挡不住 `& | < > ^`。目标工程里若存在名为 `a&calc.ts` 的文件，`cmd /c code.cmd a&calc.ts` 会被拆成两条命令。

**修复**：拆出平台相关文件 —— `editor_windows.go` / `editor_other.go`，Windows 侧不再走 `os/exec` 的参数转义，而是自己拼完整命令行交给 `SysProcAttr.CmdLine`：

```go
cmd.SysProcAttr = &syscall.SysProcAttr{CmdLine: "/c " + strings.Join(parts, " ")}
```

每个参数用双引号包裹（cmd 在引号内不解释 `& | < > ^`），并把仍会展开的 `%` 与 `!` 用 `^` 转义。类 Unix 侧不受影响（参数本来就是独立 argv）。

### 1.4 前端：外部编辑器打开前的确认

后端只能保证"命令来自白名单"，管不了"这一次是不是用户真想在这台机器上起进程"。

**实现**：store 新增通用确认机制（`askConfirm` / `answerConfirm` + `ConfirmDialog` 组件），并提供统一入口：

```ts
async openExternally(target) {
  const ok = await get().askConfirm({
    title: '在本机唤起外部编辑器',
    message: `Studio 会在运行服务的这台机器上启动「${editorId}」进程…`,
    detail: where,
    confirmText: '打开',
    skipKey: 'studio.skipEditorConfirm',
  });
  if (!ok) return;
  ...
}
```

支持"以后不再询问"（记 localStorage）。Inspector 与 SourcePanel 的调用点都改为走这个入口。

## 2. 编辑正确性批次

### 2.1 `anchor.hash` 漂移校验（第二轮 P0-9 只做了一半）

第二轮只在 `analyze.mjs` 生成了 `anchor.hash`，但**没有任何地方消费它**。真正的风险是：用户加载分析结果后、提交前，源码被外部改过 —— 同一个 `nodeId` 已经指向别的内容，照旧执行会**改错位置**，而 diff 上看起来"改的确实是那个字面量"。

**实现**：

- `edit.mjs` 新增 `assertNoDrift(analysis, op)`，在 `planEdit` 分发前统一执行：拿 `op.anchorHash` 与**用当前文本重新分析**出的同一节点比对，不一致抛 `EANCHOR`；
- `types.ts` 的 `Op` 通过交叉类型支持 `anchorHash`；
- **store 在 `submit` 里自动填充**（而不是让各调用点自己填），这样属性面板、结构画布、重命名、诊断修复所有入口天然受保护；
- 前端收到 `EANCHOR` 时提示并立即 `refreshAnalysis`，让界面回到真实状态。

缺失 `anchorHash` 时跳过校验（不阻断合法操作），最后一道防线仍是 Go 侧 apply 时的文件级 SHA 比对。

**测试**：3 个新用例（一致放行 / 被外部改过必须拒绝且码为 `EANCHOR` / 不带 hash 不阻断）。

### 2.2 写盘部分失败时，已改文件丢失撤销能力

`Apply` 第二阶段中途失败会直接 `return`，**不 `pushHistory`** —— 磁盘已经改了前几个文件，undo 栈里却没有这条记录，用户只能靠 `.bak` 手工恢复。

**修复**：失败时把已成功写入的部分（`record.Files` 只含写成功的）推进历史并清空 redo 栈，错误消息明确提示"可用「撤销」回退"。

### 2.3 撤销/重做的写盘失败会留下"卡死"状态

`Switch` 虽然是先全校验再写，但写盘中途失败仍是半成品：一部分文件已到目标态，而 `want` 是整批 SHA，**再点一次撤销会因为基线不匹配而永久卡住**。

**修复**：记录每个文件的原始内容，任一写入失败就把已写的按原内容回滚，做到"全或无"：

```go
done := make([]task, 0, len(tasks))
for _, t := range tasks {
    if err := writeFileAtomic(t.path, []byte(t.text)); err != nil {
        for i := len(done) - 1; i >= 0; i-- {
            _ = writeFileAtomic(done[i].path, []byte(done[i].current))
        }
        return fmt.Errorf("写入 %s 失败（已回滚 %d 个文件，本次 %s 未生效）：%w", ...)
    }
    done = append(done, t)
}
```

### 2.4 历史文件含源码正文 + 持锁读盘

两处一起改（`server/edit.go`）：

- **`persistLocked` 只写元数据**：撤销/重做栈是会话级的，落盘的 `Before/After` 正文重启后再也用不到，却会让源码长期留在配置目录（违反"源码正文不进持久缓存"），且 200 条 × 多文件全文会持续膨胀。现在只留 `path` + 前后 SHA；
- **读盘移出锁外**：新增 `loadFromDisk` + `ensureLoaded`（读盘在锁外、写入时处理"读盘期间别人已填过"的竞态）。原来 `History` / `findRecord` 在持有全局锁时做磁盘 IO，大历史文件会把所有编辑请求一起卡住。

> 行为一致：重启后可以查看历史，但不能跨会话撤销（磁盘上本来就没有正文）—— 这一点现在实现与声明终于自洽了。

## 3. 主题批次

### 3.1 实时预览把 `.dark` 的 token 当成 `:root`

第二轮修好了"key 取错段"，但仍把草稿统一压成 `--token` 并写进 `:root`。于是 `.dark` / `[data-density]` 下的 token 预览颜色是错的（两个选择器里同名 token 还会互相覆盖），而**保存走的是精确 selector** —— 预览与落盘结果不一致。

**修复**：改成按选择器分组下发。

- `store/studio.ts` 新增 `themeGroupsOf()`：`file|selector|token#occurrence` → `{ [selector]: { '--token': value } }`（剥掉 occurrence 后缀、保留 selector）；
- `preview/src/probe.ts` 的 `applyThemeVars(groups)` 按选择器生成多块 CSS，变量名仍做 `/^--[A-Za-z0-9_-]+$/` 兜底。

### 3.2 5 类主题问题共用一个 `ST008`，面板无法分类

**修复**：拆成独立码，语义与级别一一对应：

| 码 | 含义 | 级别 |
|---|---|---|
| `ST008` | 非法颜色写法 | error |
| `ST012` | 语法合法但无法静态求值（`color-mix` 等） | info |
| `ST013` | 同一选择器内重复声明 | warning |
| `ST014` | `:root` 缺少必需 token | error |
| `ST015` | 对比度不足 | warning（不阻断，按 §5.7.4） |

顺带删掉了死代码 `ratio >= AA_LARGE ? 'warning' : 'warning'`（三元两支相同），改为在消息里区分严重程度（低于 `AA_LARGE` 时补充"大字号要求"）。

### 3.3 深色模式对比度是永久盲区

`valueOf` 只在**当前选择器块内**查配对。而 `.dark` 通常只覆盖 `--background`、`--foreground` 仍继承 `:root` —— 这种最常见写法会让整条检查被跳过。

**修复**：取值遵循 CSS 的实际级联（当前选择器 → 回退 `:root`）。测试覆盖了"`.dark` 只有 `--background`、前景回退到 `:root`"的场景。

## 4. 诊断批次

### 4.1 `ST006` 真正查基类（不再靠降级掩盖）

第二轮把 ST006 降到 warning 来掩盖误报 —— 那等于把"真的写错方法名"也一起放过去了。

**修复**：`analyzer/src/enums.mjs` 新增 `extractHandlerBaseMethods()`，从框架的 `handler/handlerBase.ts` + `handler/handlerViewBase.ts` 提取类成员名（带 mtime 缓存，避免每次 `page.analyze` 重复解析框架文件）。`analyzePage` 接收 `baseHandlerMethods` 并传入 `collectIssues`：

- **拿到基类清单** → 本类 + 基类都不含该方法才报 **error**；
- **拿不到**（编辑链路没传框架路径）→ 保持 warning，宁可不报也不误伤。

**测试**：`ST006：查得到框架基类时，基类方法不报错、写错的方法名才报 error`。

### 4.2 L3 分级

原来只有 L1 / L2。**修复**：新增 `detectForwardingShell()`，只认两种**确定**的"转发壳"形态 —— 重导出（`export ... from`）与动态装配（`import(...)` / `React.lazy(...)`）→ L3 + `ST103`。

刻意**不**判"`export default` 指向标识符"：`apps/demo` 的页面正是 `const P = () => <ViewRoot .../>; export default P;`，那样会把正常页面误降成只读。

### 4.3 `pages.list` 带识别级别

左栏需要在"点开之前"就能区分可编辑与只读。**修复**：`pages.mjs` 新增 `cheapLevel()`（只读一次入口文本，不做完整 AST），返回 `level`；前端左栏对非 L1 页面标出 `L2` / `L3` 并附 tooltip。精确级别仍以 `page.analyze` 为准（按需解析）。

### 4.4 `ST011`：新增页面必须提示"菜单要单独登记"

路由由 `vite-plugin-pages` 自动发现（建目录即生效），但后端菜单是另一份数据（mock 的 `menuData.key`），不会跟着同步。**修复**：`templates.mjs` 的 `pageTemplates` 返回值带上 `notes`（含 `ST011`），随模板一起透传给前端，避免用户以为菜单也建好了。

## 5. 交互批次

### 5.1 值改动改为草稿 + 未保存标记 + 快捷键

原文承诺"改属性 → 本地草稿生效 → 标未保存 → Ctrl+S 保存"，实现是 `onBlur` 即落盘。

**实现**：

- store 新增 `staged: StagedOp[]` 与 `stageOp / unstageOp / discardStaged / saveAllStaged`；草稿键为 `${kind}:${target}`（同目标同操作只留最后一次，避免堆出互相矛盾的条目）；
- `PropEditor` 的所有值控件（字面量 / 枚举引用 / 成员引用 / handler 引用 / 焦点行绑定 / 原始表达式）改为**只暂存**；属性行上出现「未保存」徽标；
- `submit` 增加 `forceApply`：用户显式点保存时跳过 diff 确认；
- 顶栏显示「待保存 N」+「保存全部」+「丢弃」；
- **全局快捷键**：`Ctrl+S` 保存草稿（阻止浏览器保存网页）、`Ctrl+Z` / `Ctrl+Shift+Z` 撤销重做（焦点在输入框内时不拦截，让用户先撤销自己刚敲的字）；
- 切换页面/项目时清空草稿并提示（草稿里的 `op.target` 是当前页面的节点 id，跨页面必然失效）。

> **注意**：这里把设计稿 §7.1 的「待应用计划 (N)」落地为「待保存 N」。原因是服务端一次只处理一个 op，真正的"计划队列 + 批量 apply"需要新增批量接口；当前实现是"草稿队列 + 逐个落盘"，能力等价且不需要改协议。设计稿需同步这个措辞。

**结构性改动仍走原链路**（生成计划 → 看 diff → 确认）—— 删除、新增、重排、重命名的风险远高于改一个值。

### 5.2 属性字段旁的「定位源码」图标

原来只有**只读**节点才有 Crosshair。**修复**：新增 `LocateButton`，每个有锚点的字段右侧都可一键切到「源码」Tab 并定位到该行。

### 5.3 问题面板点击跳转源码行

原来只做 `selectNode` + 切「属性」Tab。**修复**：

- store 新增一次性定位 `sourceFocus` + `focusSource / clearSourceFocus`；
- `SourcePanel` 优先响应它（诊断不一定对应语义节点，例如缺 token、语法错误）；
- 诊断指向的文件若不在页面文件清单里（例如框架主题 css），临时并入下拉，否则 Select 的 value 找不到 option，界面上看不出在看哪个文件。

### 5.4 编辑历史「查看详情」不再是假详情

原来只是重复拉一次列表然后打印"请用撤销"——而接口本来就带 `impacts`。**修复**：`HistoryDetail` 渲染真实的 before→after 片段（含文件相对路径与改动标签），并说明"服务重启前写入的历史只保留元数据"。
