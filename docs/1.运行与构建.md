# App/Web 环境变量配置说明

## 概述

`app/web` 项目使用 Vite 作为构建工具，支持多环境部署。项目提供了多个环境配置文件，用于不同场景下的环境变量配置,使用不同后缀,可覆盖基础环境配置中的参数。

## 快速运行

1.node: 推荐24.11.1
   可以使用nvm管理多个node版本: nvm use 24.11.1

2.安装pnpm: 安装文档 `https://pnpm.io/zh/installation`

3.安装依赖:在根目录运行 `pnpm install`

4.运行项目: 在根目录运行并启动mock服务器 `pnpm dev:mock`

## 环境配置文件

### 1. `.env` - 通用配置

适用于所有环境的通用配置，包含基础的应用设置：

```env
# AUTH_TOKEN 缓存失效时间（单位：毫秒）
VITE_AUTH_TOKEN_EXPIRE_TIME = 7200000

#界面标题
VITE_TITLE = "WMS"

# 端口号
VITE_SERVER_PORT = 7000

# 登录页面
VITE_BASE_URL = "http://127.0.0.1:3001/api"
VITE_LOGIN_URL = "/login"

# 接口地址
# 获取菜单地址
VITE_API_LOGIN = "/login"
VITE_API_MENU = "/menu"
```

## 环境变量说明

### 核心配置项

| 变量名 | 说明 | 示例值 | 适用范围 |
|--------|------|--------|----------|
| `VITE_ENV` | 环境标识 | `dev`, `production`, `mock` | 所有环境 |
| `VITE_SERVER_PORT` | 本地开发服务器端口 | `7000`, `9900` | 本地开发 |
| `VITE_BASE_URL` | API基础地址 | `http://127.0.0.1:3001/api` | 所有环境 |
| `VITE_TITLE` | 应用标题 | `"WMS"` | 所有环境 |

### 功能配置项

| 变量名 | 说明 | 默认值 | 适用范围 |
|--------|------|--------|----------|
| `VITE_LOGIN_URL` | 登录页面路径 | `/login` | 所有环境 |
| `VITE_AUTH_TOKEN_EXPIRE_TIME` | Token过期时间(毫秒) | `7200000` | 所有环境 |
| `VITE_API_LOGIN` | 登录接口地址 | `/login` | 所有环境 |
| `VITE_API_MENU` | 菜单接口地址 | `/menu` | 所有环境 |

## Windows 桌面版（Tauri 2）

桌面版复用 `apps/demo` 的 React 页面和框架源码。开发时启动 Vite（`127.0.0.1:7000`）和仓库 Mock（`127.0.0.1:3001`）；安装包内置前端资源，正式运行只连接业务后端，不启动 Node.js 或 Mock。

### 环境准备

- Node.js 推荐 24.11.1 或更高版本；pnpm 使用根 `package.json` 指定的 10.13.1。
- Windows x64、Rust stable MSVC 工具链（`x86_64-pc-windows-msvc`）。
- Visual Studio Build Tools 的“使用 C++ 的桌面开发”、MSVC 和 Windows SDK。
- WebView2 Evergreen Runtime。
- 首次构建需要下载 Rust crates、NSIS 等依赖，需具备网络访问条件。

在仓库根目录执行：

```powershell
corepack pnpm install --frozen-lockfile
corepack pnpm desktop:info
```

`corepack pnpm` 会遵循仓库声明的版本，无需更改系统全局 pnpm；若当前 pnpm 已是对应版本，下文可直接使用 `pnpm`。

### 开发运行

```powershell
pnpm dev:desktop
```

该命令由 Tauri 自动启动前端与 Mock，等待前端就绪后打开 `WMS` 窗口。不要同时运行另一份 `pnpm dev:mock`；端口冲突时先关闭已有开发会话。前端支持热更新，Rust 壳变更由 Tauri 重新编译。结束整个开发会话使用终端 `Ctrl+C`，并检查 7000/3001 端口已释放。

桌面脚本设置 `VITE_APP_TARGET=desktop`；业务环境仍使用 `.env.mock`。Turbo 的 `dev:mock.passThroughEnv` 显式传递该标识。普通 `pnpm dev:mock` 和 `pnpm build` 保持 Web 行为，不需要 Rust 工具链。

桌面使用 `HashRouter`，地址形如 `http://tauri.localhost/#/base/form`。业务菜单仍填写 `/base/form`；登录地址仍为 `/login`，不要在业务配置中添加 `#`。框架通过可选 `LoginNavigation` 适配器处理首次鉴权、401 和退出登录，Web 默认继续使用原路径导航。不同 Origin 的 localStorage 不共享，开发登录状态不会自动迁移到正式桌面程序。

### 桌面窗口与框架本地接口

桌面窗口通过 `decorations: false` 隐藏系统标题栏。登录页与主界面右上角统一使用框架的 `WindowControls` 组件渲染最小化/最大化/关闭按钮组（普通浏览器自动不渲染）；登录后也可从头像菜单选择“关闭系统”。顶部空白区域支持拖动窗口，双击可最大化/还原。关闭请求不清除登录状态，“退出登录”仍独立保留。

业务代码统一从 framework 调用，不需要直接安装或引用 Tauri SDK：

```tsx
import { TauriUtils, WindowControls } from '@jl/framework';

// 窗口控制按钮组：仅在 Tauri 桌面环境渲染；深色背景的窗口栏传 variant="light"。
<WindowControls variant="light" />

if (TauriUtils.isAvailable()) {
  try {
    await TauriUtils.closeCurrentWindow();
    await TauriUtils.minimizeCurrentWindow();
    await TauriUtils.toggleMaximizeCurrentWindow();
  } catch {
    // 根据业务交互显示窗口控制失败提示。
  }
  // 订阅最大化状态（先同步初始值），返回取消订阅函数；
  // 拖动区双击、系统贴靠等外部变化也会推送。
  const unlisten = await TauriUtils.watchCurrentWindowMaximized((maximized) => {});
}
```

`isAvailable()` 检测实际 Tauri 运行环境，普通浏览器、桌面前端的浏览器预览和 SSR 均返回 `false`，界面不显示窗口控制入口。各窗口方法按需加载 SDK 并请求对应原生命令，保留原生窗口事件语义；非桌面调用或原生调用失败会拒绝 Promise，不会调用浏览器的 `window.close()`，也不会强制退出进程。

窗口配置或 capability 变更后需要重启 `pnpm dev:desktop`，仅刷新前端不会重新应用这些配置。后续本地能力可继续封装在 `packages/framework/src/utils/tauriUtils`，并在应用 capability 中按需授权。

### 生产 API 与安全配置

当前 `.env.production` 的 `https://api.example.com` 是占位地址，仅能用于验证打包流程。发布前必须完成以下配置：

1. 在 `apps/demo/.env.production.local` 配置实际 HTTPS API 基础地址，例如 `VITE_BASE_URL=https://wms.example.org/api`；该本地覆盖文件已被 Git 忽略。URL 需要包含后端实际要求的 `/api` 前缀。
2. 同步修改 `apps/demo/src-tauri/tauri.conf.json` 的 `app.security.csp.connect-src`，将占位 Origin `https://api.example.com` 替换为实际 Origin，例如 `https://wms.example.org`，保留自身及 Tauri IPC 来源。
3. 后端 CORS 允许 Windows 桌面默认 Origin `http://tauri.localhost`，开发环境按需允许 `http://127.0.0.1:7000`。核对实际 WebView Origin，处理 OPTIONS，允许 `Content-Type` 和 `Authorization` 请求头。
4. 登录响应必须返回 `Authorization` Token，并设置 `Access-Control-Expose-Headers: Authorization`，否则 Axios 无法读取 Token。
5. 使用受信任的 HTTPS 证书，不忽略 TLS 校验，不关闭 CSP 或 WebView 安全限制。

环境变量在构建期注入，修改 API 地址后需要重新打包；`VITE_*` 对前端可见，不能存放服务端密钥。CSP 和 CORS 是独立限制，两者都需要正确配置。

生产 CSP 不允许 Mock/HMR 地址；`devCsp` 单独放行开发连接。为支持 Ant Design CSS-in-JS 和内联布局样式，样式元素与属性允许内联样式，脚本仍保持生产限制。原生 capability 只绑定 `main` 窗口，在 `core:default` 基础上按需开放 `core:window:allow-close`、`core:window:allow-minimize`、`core:window:allow-toggle-maximize` 和 `core:window:allow-start-dragging`（`is_maximized` 与拖动区双击最大化已由 `core:default` 内的 `core:window:default` 覆盖），不开放 shell、文件系统或原生 HTTP。

### 打包与产物

```powershell
pnpm build:desktop
```

该命令先执行 TypeScript 检查与桌面前端构建，再编译 Rust 并生成 NSIS 安装器：

- 前端资源：`apps/demo/dist-desktop/`，与 Web 的 `dist/` 隔离。
- Windows 程序：`apps/demo/src-tauri/target/release/wms.exe`。
- 安装器：`apps/demo/src-tauri/target/release/bundle/nsis/*-setup.exe`。
- 若设置 `CARGO_TARGET_DIR` 或显式编译 target，Rust 产物位置会相应变化。

终端用户不需要 Node.js、pnpm 或 Rust。安装器使用 `downloadBootstrapper`，目标机器缺少 WebView2 时会联网安装 Runtime；离线环境需要另行改用 `offlineInstaller` 并验证安装包。

内部验证暂用产品名 `WMS`、版本 `0.1.0`、identifier `com.frontark.wms` 和初始化图标。正式分发前确定组织自有 identifier、产品图标与签名安排，发布后保持 identifier 稳定。未签名程序可能触发 SmartScreen。首期不包含自动更新、托盘、外链 opener、本地数据库、sidecar 或其他平台安装包。

### 常见问题

| 现象 | 检查项 |
|---|---|
| Tauri 一直等待前端 | 7000 端口是否冲突、Vite 是否启动失败；检查 hook 输出 |
| Mock 无响应 | 3001 端口占用或 Mock 编译错误；不要重复启动开发会话 |
| 登录返回 200 但提示无 Token | 后端是否暴露 `Authorization` 响应头 |
| 开发能请求、安装包不能请求 | 正式 API 地址、桌面 Origin 的 CORS、生产 CSP 白名单与证书 |
| Rust 链接失败 | MSVC、Windows SDK 与 MSVC Rust 工具链是否完整 |
| 安装器依赖下载失败 | NSIS/WebView2 下载源和网络访问；不要据此关闭安全配置 |
| 修改 API 后没有生效 | 配置为构建期注入，重新打包；不要在 Turbo 缓存中混用 Web 与桌面产物 |
